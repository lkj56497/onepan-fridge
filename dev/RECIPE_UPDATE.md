# 레시피 업데이트 절차 (냉장고를 맡겨줘)

**사용자가 "레시피 업데이트해"라고 직접 지시했을 때만 진행한다. 혼자 판단해서 시작하지 않는다.**
매달 오는 알림은 "업데이트할 때가 됐다"는 안내일 뿐이고, 업데이트 자체는 사용자의 지시가 있어야 한다.

## 준비물
- `dev/accounts.json`: 레시피를 가져온 계정 목록, 마지막 확인 날짜(`last_checked`), 앱에 이미 있는 레시피 제목(`existing_titles`)
- `dev/app-source.html`: 앱 원본 (레시피 데이터 `const R = [...]` 포함)
- 사용자 컴퓨터의 내장 브라우저(Claude 데스크톱 앱)에 인스타그램 로그인이 되어 있어야 한다. 안 되어 있으면 사용자에게 로그인을 부탁한다.

## 1. 기존 계정에서 새 게시물만 가져오기
- `accounts.json`에서 status가 "수집함"인 계정을 모두 연다.
- `last_checked` 이후에 올라온 게시물만 읽는다. 그 이전 게시물은 이미 처리했으므로 다시 읽지 않는다.
  - 게시물 날짜는 게시물 페이지 HTML의 `og:description`("… - 계정 - November 3, 2026: …")에서 확인한다.
- 프로필 그리드는 실제 스크롤 이벤트(브라우저 `computer` scroll)를 해야 더 로드된다.
- 캡션은 같은 출처에서 `fetch(게시물주소)` 후 `og:description`을 읽는다. 자바스크립트 실행은 45초 제한이 있으니 백그라운드로 돌리고 결과를 나눠 받는다.

## 2. 새 계정 찾기
- 인스타 검색창에 `search_keywords`를 하나씩 넣어 계정을 찾는다.
- 원팬(프라이팬 하나)·간단요리·자취요리 계정 중 `accounts.json`에 없는 곳만 새로 확인한다.
- 캡션에 재료/정량/순서가 글로 적힌 계정만 수집한다. 영상에만 있으면 "제외"로 기록한다.
- 원팬맨 관련 계정(이름에 원팬맨이 들어간 계정)은 제외한다.

## 3. 레시피로 만들기 규칙
- **중복 금지**: `existing_titles`에 있는 메뉴와 같은 요리(이름만 다르고 사실상 같은 요리 포함)는 넣지 않는다. 이번에 새로 모은 것끼리도 겹치면 하나만 넣는다.
- **도구를 두 개 쓰는 요리는 넣지 않는다**(예: 팬 + 면 삶는 냄비, 전자레인지 + 팬). 팬·냄비 하나, 또는 전자레인지 하나로 끝나는 요리만 넣는다.
- 광고·제품 홍보만 있는 게시물, 밀키트를 데우기만 하는 게시물, 오븐·에어프라이어가 꼭 필요한 요리, 디저트 위주 게시물은 뺀다.
- 원문 문장을 그대로 쓰지 않고 새로 쓴다. 출처·계정명·영상 링크는 넣지 않는다.
- 정량이 없는 재료는 보편적인 양으로 채우고 세 번째 값을 1로 표시한다(앱에 "보통" 배지로 보임).
- 형식(기존과 동일):
  `{"t":제목,"s":인분,"n":메모(선택),"i":[[재료,정량(,1)],...],"p":[순서...],"tm":[단계별 시간...],"tip":한 줄 팁,"id":제목,"k":종류}`
  - `k`(음식 종류)는 한식·중식·양식·일식·디저트·기타 중 하나. 파스타·스프·리조또는 양식, 덮밥(규동·오야꼬동)·우동·카레는 일식, 짬뽕·짜장·마라는 중식, 팟타이 같은 동남아 요리와 국적이 섞인 퓨전은 기타.
  - `p`와 `tm`의 개수는 반드시 같아야 한다.
- 새 재료가 생기면 `app-source.html`의 `MAP`(비슷한 재료 묶기)과 `GROUPS`(재료 카테고리)에 추가한다. 카테고리에 없는 재료는 "기타"로 빠지니 꼭 확인한다.

## 4. 앱에 반영하고 올리기
1. 새 레시피를 `dev/new-recipes/`에 JSON으로 저장하고 `app-source.html`의 `const R = [...]` 끝에 합친다.
2. 화면이 깨지지 않는지 확인한다(카드 수, 상세 화면).
3. `bash dev/build.sh <versionCode+1> <새 버전명>`으로 `index.html`, `onepan-fridge.apk`, `install.html`을 다시 만든다.
4. claude.ai의 "냉장고를 맡겨줘" 아티팩트도 `app-source.html` 내용으로 다시 게시한다.
5. `accounts.json`의 `last_checked`를 오늘 날짜로, `existing_titles`를 새 목록으로, 계정 목록과 memo를 갱신한다.
6. 커밋하고 `main`에 푸시한다. 1~3분 뒤 https://lkj56497.github.io/onepan-fridge/install.html 에서 반영을 확인한다.
7. 사용자에게 새로 추가된 레시피 수, 새로 찾은 계정, 제외한 계정을 알린다.

## 안드로이드 빌드 주의
- `resources.arsc`는 압축하지 않아야 안드로이드 11 이상에서 설치된다(`dev/android/apktool.yml`의 doNotCompress). 지우지 말 것.
- versionCode는 매번 1씩 올린다. 낮추면 기존 앱 위에 설치되지 않는다.
- 서명은 uber-apk-signer의 내장 디버그 키를 쓴다. 다른 키로 서명하면 기존 앱 위에 업데이트 설치가 안 된다.
